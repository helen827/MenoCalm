# Step 3 审计：删除/导出/注销闭环方案

> 对应计划：`docs/Audit-First-Execution-Plan.md` 的 Step 3  
> 目标：确认当前三个入口的真实状态，并定义可落地的完整链路（UI -> 业务 -> 存储 -> 回执）。

---

## 1. 审计结论（当前状态）

- `设置`页已有三个入口文案：`导出我的数据`、`删除我的数据`、`注销账号`。
- 这三个入口目前均为 UI 展示，**未绑定业务 action**（无点击回调）。
- 当前唯一实际“退出”逻辑是 `AuthSession.logout()`，只重置内存态 `phoneNumber/currentUserID`，不覆盖“导出/删除/注销账号”完整语义。

---

## 2. 三个入口现状盘点

| 入口 | 当前位置 | 当前逻辑 | 缺失项 |
|---|---|---|---|
| 导出我的数据 | `Features/Profile/ProfileViews.swift` -> `SettingsView` | 仅显示一行菜单，无 action | 导出任务生成、范围定义、导出文件、完成回执 |
| 删除我的数据 | `Features/Profile/ProfileViews.swift` -> `SettingsView` | 仅显示一行菜单，无 action | 二次确认、删除范围、软删/硬删策略、执行回执 |
| 注销账号 | `Features/Profile/ProfileViews.swift` -> `SettingsView` | 仅显示一行菜单，无 action | 服务端注销、token 失效、本地清理、登录态迁移 |

补充：
- `AuthSession.logout()` 已存在（`App/AuthSession.swift`），但仅为“会话退出”动作，不等价于“注销账号”。

---

## 3. 目标定义（产品与合规口径）

## 3.1 导出我的数据（Data Export）

- 用户可触发一次导出请求。
- 导出包含该用户可识别数据集合（见第 4 节）。
- 导出成功后可获得可分享文件（建议 JSON + 可读 Markdown 摘要）。

## 3.2 删除我的数据（Data Deletion）

- 支持“删除本地数据”与“删除云端数据（若已接后端）”。
- 删除应可追踪：记录请求时间、执行结果、失败原因。
- 删除完成后本地应进入“空白新用户态”。

## 3.3 注销账号（Account Deactivation）

- 语义 = 账号停用/删除 + 会话退出 + 数据清理策略执行。
- 与“仅退出登录”明确区分，避免误导用户。

---

## 4. 数据范围定义（本轮定稿）

## 4.1 导出范围（必须包含）

- 账号信息：手机号脱敏、用户标识
- 日记/记录：`JournalEntry` 及提取结构
- 对话洞察：`ConversationInsight`
- 报告：`ReportSnapshot`
- 呼吸练习：完成记录/统计
- 同意记录：隐私政策/协议/免责声明同意版本与时间

## 4.2 删除范围（必须包含）

- 本地数据库中的所有用户业务数据（按 `userID`）
- 本地 token（后续迁移到 Keychain）
- 同步队列与失败历史（按 `userID`）

## 4.3 不删除范围（默认）

- App 运行配置（环境/超时等 app 级配置）
- 非用户私有的静态资源（内置内容、说明文档）

---

## 5. 真实实现链路方案（最小可用）

## 5.1 导出我的数据

1. UI：点击 `导出我的数据` -> 弹窗确认
2. 业务：`AppViewModel.exportMyData()`
3. 存储：聚合 DB/本地存储数据 -> 序列化为 JSON 文件
4. 回执：展示“导出成功/失败”，支持系统分享面板

失败处理：
- 无数据：提示“暂无可导出数据”
- 写文件失败：提示重试 + 记录内部告警事件

## 5.2 删除我的数据

1. UI：点击 `删除我的数据` -> 二次确认（输入“删除”）
2. 业务：`AppViewModel.deleteMyData(scope:)`
3. 存储：
   - 本地：按 `userID` 软删/硬删（建议硬删业务表，保留最小审计记录）
   - 远端：调用删除接口（若已接入）
4. 回执：清理完成后回到欢迎页，提示“数据已删除”

失败处理：
- 本地删除失败：阻断并提示
- 远端删除失败：给出“部分完成”状态和后续重试入口

## 5.3 注销账号

1. UI：点击 `注销账号` -> 风险说明 + 二次确认
2. 业务：`AppViewModel.deactivateAccount()`
3. 存储：
   - 先服务端注销（若可用）
   - 再 `token` 失效（`AuthTokenManager.invalidate`）
   - 再本地数据清理（复用删除流程）
4. 回执：返回 onboarding，显示注销完成状态

---

## 6. 需要新增的最小接口（应用层）

- `exportMyData() async throws -> URL`
- `deleteMyData(deleteRemote: Bool) async throws`
- `deactivateAccount() async throws`
- `logoutOnly()`（保留现有快速退出语义）

说明：
- “注销账号”与“退出登录”必须是两个独立 action。

---

## 7. 风险与防呆

| 风险 | 说明 | 防呆措施 |
|---|---|---|
| 误触发删除 | 用户误点危险操作 | 二次确认 + 明确后果文案 |
| 语义混淆 | 注销与退出混为一谈 | 按钮与弹窗明确区分 |
| 部分删除 | 本地成功、远端失败 | 部分完成回执 + 重试任务 |
| 审计缺失 | 合规动作无记录 | 记录 `audit event`（请求/成功/失败） |
