# Step 4 定义：最小闭环验收标准（单人执行版）

> 对应计划：`docs/Audit-First-Execution-Plan.md` 的 Step 4  
> 目标：定义唯一上线前闭环门槛，保证“按清单执行 -> 结论一致”。

---

## 1. 最小闭环（MVP Gate）

闭环路径（必须整链通过）：

`登录 -> AI 对话记录 -> 结构化提取 -> 报告生成 -> 呼吸练习完成 -> 社区浏览 -> 合规入口可达`

---

## 2. 验收清单（可勾选）

## 2.1 账户与进入

- [ ] 首次进入可完成同意流（隐私政策/用户协议/免责声明）
- [ ] 手机号登录后进入主界面，状态正确（非 guest）
- [ ] token 失效时可触发会话失效提示并回到登录态

## 2.2 AI 对话与记录

- [ ] 用户输入后可收到 AI 回复（非空、非崩溃）
- [ ] 对话内容可落地为记录（至少 1 条）
- [ ] 高风险语句触发安全提示模板（不输出诊断结论）

## 2.3 结构化提取与报告

- [ ] 对话可提取症状/诱因（至少一项结构化字段）
- [ ] 报告页可显示本期结论卡与基础统计
- [ ] 报告在无数据时有 empty 状态提示

## 2.4 呼吸练习闭环

- [ ] 任一练习可开始并完成一次完整 session
- [ ] 完成后计数或记录有变化（可观察）
- [ ] 练习推荐卡可根据记录变化（基础联动）

## 2.5 社区与内容

- [ ] 社区页可加载官方与用户内容（非纯静态空页）
- [ ] 下拉刷新可触发数据更新（成功或错误提示）
- [ ] 发布页显示社区规范提示

## 2.6 合规与设置

- [ ] 设置页可打开隐私政策/用户协议/免责声明
- [ ] 危险操作入口（导出/删除/注销）可见且文案清晰
- [ ] 至少有内部告警/运行事件可见（用于验收可观测性）

---

## 3. 失败判定（Fail Criteria）

任一项命中即判定“不通过”，不得进入上线候选：

1. **主链路中断**：登录后无法完成 AI->报告->练习 任一关键跳转
2. **数据不可留存**：完成记录后重启应用，核心数据全丢失
3. **风险边界失效**：高风险输入无拦截提示或给出诊断性结论
4. **无异常反馈**：网络失败/空数据无提示，用户无可行动作
5. **合规入口不可达**：政策文档无法从设置页访问

---

## 4. 执行方法（单人）

- 每次仅验证一条完整主链路，避免碎片化点测。
- 验收记录使用“截图 + 结论 + 问题编号”三件套。
- 问题按 P0/P1/P2 分类：
  - P0：阻断闭环
  - P1：功能可用但不稳定
  - P2：体验优化项
